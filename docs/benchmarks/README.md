# Benchmarks

What PuffPuff measures, how, and how it compares with OpenFL's native backend. The numbers come from scripts in
`tools/bench`, from one machine and one run of them, so rerun them before quoting a number elsewhere.

## Categories

One page per area, each with its cases, what they do, and its comparison with OpenFL where there is one.

| Page | Covers | OpenFL baseline |
|---|---|---|
| [Text](text.md) | shaping and laying out lines, screens of labels | yes |
| [Vector graphics](vector-graphics.md) | tessellating and drawing fills and strokes | not yet |
| [Sprites and quads](sprites.md) | batching and drawing textured quads | not yet |
| [Images](image.md) | CPU pixel operations of `lime.graphics.Image` | not yet |
| [Math and SIMD](math-and-simd.md) | matrices, vectors and batched arithmetic | not yet |

"Not yet" means those cases only track PuffPuff against its own recorded baseline. A claim of being faster than
OpenFL for them needs the same scene measured on OpenFL first.

## Method

Cases are in `tools/bench/Cases.hx`, named `area.subject[.variant]`; a page covers the names that start with its
area. `tools/bench/run.sh` runs each case in two passes, each in its own process:

- **Time:** best of 15 samples, each long enough to be measured reliably. The pages show the median, per
  operation: a run of a case does the number of operations in the "Operations per run" column (pixels, labels,
  shapes; 1 for a whole frame or a single matrix product), and the time and allocation are divided by it.
- **Allocation:** bytes allocated per operation, exact because the pass runs with `ASH_GC_TLAB=0`, and growth of live
  memory across a third batch of runs, as a leak signal.

A case can carry a correctness check and a checksum of its output. A failed check, or a changed checksum, fails the
run, so a speed-up that changes the output does not pass. A run is compared with the stored baseline for the same
machine and tier and fails on a slowdown beyond the tolerance (30% by default).

**Frame cases** (`gpu.frame.*`) draw into an offscreen texture. `.submit` is the time to build the frame and submit
it, without waiting for the GPU, so it is the CPU cost of the frame. `.readback` waits for the GPU and copies the
512 x 512 frame to the CPU; that copy costs about 0.8 to 0.9 ms by itself, which a frame that is presented does not
pay, so `.readback` is an upper bound on a frame's time and `.submit` a lower one.

**Tiers.** The baseline is recorded on Ash's LLVM tier (`--mode jit --jit-tier llvm`), the one that runs ahead of
time at full optimisation. The default hybrid tier is not recorded: Ash 0.1.14 drops strokes there in some runs of
the whole suite (reported to the Ash project), and a baseline from a failing run is not stored.

**Native text library.** Text shaping and the glyph atlas live in `blinc_abi` (Rust). A debug build of it is 40 to
80 times slower at shaping a new line, so every number is from the release build. The build stages
`../blinc_abi/target/release/libblinc_abi.dylib` and warns when only a debug one exists; build it with
`cargo build --release` in `../blinc_abi`.

## The baseline

<!-- bench-meta -->
PuffPuff `4a27384` on ash 0.1.14, llvm tier, Apple M1 Pro.

Stored in `tools/bench/baselines/`; per machine and per tier, so compare numbers only against the same machine.

## Reproducing

```sh
(cd ../blinc_abi && cargo build --release)  # once; the benchmark stages this library
tools/bench/run.sh --mode llvm              # runs everything and compares with the baseline
tools/bench/run.sh --mode llvm text         # one area: a name prefix, or several separated by commas
tools/bench/run.sh --mode llvm --baseline   # stores the run as the baseline and regenerates these pages
tools/bench/openfl/run.sh                   # OpenFL's side of the text comparison (opens a window briefly)
python3 tools/bench/docs.py                 # regenerates the tables on these pages from the baseline
```

The case tables, the line above and the OpenFL comparison are generated by `tools/bench/docs.py` between
`<!-- ... -->` markers; the rest of each page is written by hand. To add an area, name its cases `area.*`, add a page
with a `bench-table` block for that prefix, and list it above.

## Correctness and rendering checks

Besides the benchmarks, the snapshot scenes in `tools/snapshot/scenes` render headless to PNG with pixel checks:
`OpenFLShapeScene`, `OpenFLGradientScene` and `OpenFLBitmapScene` run a real OpenFL `Stage` on PuffPuff at display
scales 1 and 2, `TextCacheCheck` compares cached text lines with whole-line shaping across scripts and across a
forced atlas clear, and `MultiFlushScene` checks that many flushes in one frame draw what they should.
